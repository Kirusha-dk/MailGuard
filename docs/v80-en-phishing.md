# MailGuard v80: фишинг, нейросетевые признаки и строгая проверка FP

**Цель 98% обнаружения с примерно 10 FP на миллион писем не достигнута.** Миллион писем и почта заказчика не проверялись.

На прежних 100 000 английских писем `recall-98` обнаруживает 97,95% спама с **586 FP**. В `balanced` — 91,46% с **126 FP**. При самом строгом калибровочном ограничении `ten-ppm` обнаруживается 20,05% спама, FP — 3. Это разные рабочие точки; совместной цели нет ни в одном режиме.

На новом наборе **247 фишинговых писем из архива 2024 года** `balanced` улучшился с **142/247 (57,49%) у v79 до 174/247 (70,45%) у v80**. У `recall-98` — 230/247 (93,12%). Обычных писем в этом наборе нет: FP на нём оценить нельзя.

## Новый фишинговый тест

Весь архив Nazario-2024 исключён из нового обучения, выбора модели и калибровки. После фильтра языка и удаления совпадений осталось 247 писем с 247 разными группами первых 45 слов. Они не пересекаются по канонической идентичности или префиксной группе ни с одним разделом v79, ни с дополнительными TRAIN/SELECT/CAL.

| Модель / режим | Найдено фишинга | Recall |
|---|---:|---:|
| v79 `balanced` | 142 / 247 | 57,49% |
| v80 `ten-ppm` | 6 / 247 | 2,43% |
| v80 `strict` | 6 / 247 | 2,43% |
| v80 `target-80` | 114 / 247 | 46,15% |
| v80 `balanced` | 174 / 247 | 70,45% |

Это новый для данного исследования год **того же поставщика**, а не новый независимый поставщик. У основы v79 уже есть обучающие письма 2025 года: строгого разделения по времени здесь нет. Сам тест фишинговый; отсутствие FP в нём ничего не доказывает о защите обычной почты. Быстрый первый этап передаёт нейросети 245 из 247 писем.

## Почему нельзя подтвердить 10 FP на миллион

CLI отдельно считает долю FP среди всех оценённых писем и среди обычных. `ten-ppm` выбирает порог с бюджетом 0,001% **HAM** на SELECT/CAL — это более осторожная калибровочная цель, а не обещание на будущем потоке. При 25 208 CAL HAM округление допускает ноль FP. На новых данных ограничение может нарушаться.

Даже ноль FP на 53 303 HAM даёт одностороннюю 95%-ю биномиальную верхнюю границу примерно 56 FP на миллион HAM. Для границы 10 на миллион при нуле наблюдаемых ошибок нужно минимум 299 572 независимых репрезентативных испытаний. Та же формула применима к частоте FP на всех письмах, но знаменатель тогда — весь поток. Интервалы предполагают независимость и представительность; исторические корпуса с общими кампаниями не доказывают качество на почте заказчика.

Название `recall-98` означает настройку на 98% по SELECT/CAL. Оно не гарантирует 98% на каждом блоке или источнике. Совместная цель явно проверяется в `summary.json`; отдельно отмечается, было ли действительно оценено хотя бы миллион сообщений.

## Что изменено

- Сохранена неизменённая основа v79; добавлены отдельные NBSVM по словам и символам для фишинга. Для них использовано 52 949 и 27 384 обучающих письма соответственно.
- Дополнительные годы Nazario-2015…2023 дали 1 227 TRAIN, 176 SELECT и 345 CAL после фильтра языка, дедупликации и исключения всех исходных групп v79. Архивы проверяются по SHA256.
- Готовая английская нейросеть `sentence-transformers/all-MiniLM-L6-v2` извлекает признаки смысла. **Сам Transformer заморожен и не дообучался.** Поверх признаков обучены линейный классификатор и отдельный классификатор фишинга с нелинейными признаками: 21 042 и 12 112 писем.
- Итоговая комбинация обучается на одной половине SELECT, выбирается на другой; разделение идёт по префиксным группам. Все годы Nazario объединены в одну группу при оценке худшего источника, чтобы редкий фишинг не терялся при усреднении. CAL независим от fit.
- Нейросеть обрабатывает сообщения, у которых хотя бы один из пяти быстрых классификаторов выдаёт оценку минимум −0,5. Это заранее заданный порог вычислительного этапа; его пропуски учитываются в итоговом recall.
- Квантизованные веса английского encoder приведены к диапазону −64…63 для переносимости CPU. Каждое письмо проходит независимый нейросетевой запуск, без общей квантизации с соседними письмами. Параллельный и последовательный расчёт encoder совпали точно на проверочных входах.
- Одинаковые хешированные словесные и символьные признаки вычисляются один раз для двух NB-моделей. Проверка на 128 TRAIN-письмах дала точно те же оценки, что исходные формулы.
- Сохранённая модель и пороги зафиксированы до нового теста. Оценка может возобновляться по блокам с проверкой SHA модели, кода и состава блока. Веса после просмотра теста не менялись.

Модель использует текст с нормализованными URL и адресами. Она не проверяет доверенные результаты SPF/DKIM, происхождение отправителя или репутацию домена. Это ограничивает различение легитимных уведомлений и похожего фишинга. Для сравнения с фильтром заказчика нужны одинаковые размеченные письма и одинаковый набор доступных признаков.

## Запуск

Python 3.12. Распакуйте архив весов полностью в `model`: внутри должны остаться `model.joblib`, `base/model.joblib` и каталог `encoder`.

```bash
git clone --branch mailguard-v80-en-phishing --single-branch https://github.com/Kirusha-dk/MailGuard.git
cd MailGuard
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-v80.txt
python tools/v80_mail.py \
  --model model/model.joblib \
  --spam mail/spam --ham mail/ham \
  --profile balanced --output results/check-01
```

Поддерживается английский с уверенным определением языка. Остальные и неуверенные тексты исключаются с явными счётчиками. Одна `.eml` на письмо, отдельные папки SPAM/HAM. Повторы удаляются; при противоречивых метках удаляются обе копии. В выходных файлах нет текстов писем.

Для режима с целью высокой полноты замените профиль на `recall-98` и используйте новую выходную папку. Для более строгого FP-порога — `ten-ppm`; его низкий recall указан выше. Установка и CLI проверены на Linux, Python 3.12; отдельной проверки macOS и Windows не выполнено. После установки зависимостей письма обрабатываются локально на CPU без сети и PyTorch.

SHA256 `model.joblib`:

```text
6aa2e92b2e1ccfd764223eeea5d1c792e5ae15548ad60767be93023d690aa5c9
```

Проверены 30 тестов v77/v78/v79/v80 и настоящий MIME CLI на 60 английских письмах в `balanced` и `ten-ppm`. Решения CLI/API и одиночного/группового запуска совпали на проверенных входах; максимальная разница оценок одиночного/группового запуска — 2,21×10⁻⁹. Французское, немецкое и русское письма исключены; повторы и противоречивые метки обработаны.

## Повторить исследование

Сначала подготовьте точный набор v79 по [его инструкции](v79-en-100k.md); его опубликованный manifest должен совпасть. Для обучения нужна основа v79 с SHA `f331dc14cb289a5e27cc96904aad519cc07bc2a400e008ea71acffd200621d72` — она включена как `base/model.joblib` в архив v80.

```bash
python -m pip install -r requirements-v80-training.txt
python tools/fetch_v80_sources.py
python tools/prepare_v80_encoder.py \
  --source .cache/v80/encoder/model-source-int8.onnx \
  --tokenizer .cache/v80/encoder/tokenizer.json \
  --license-file .cache/v80/encoder/LICENSE --out .cache/v80/encoder-s7
python tools/prepare_v80_phishing.py
python tools/audit_v80_cohorts.py --output reports/v80-data-audit.json
OMP_NUM_THREADS=3 OPENBLAS_NUM_THREADS=3 MKL_NUM_THREADS=3 \
  TOKENIZERS_PARALLELISM=false python -u tools/train_v80_en.py --base model/base/model.joblib
```

Подготовка и fit требуют новых выходных папок. Для повторной оценки готовой модели с теми же данными:

```bash
python tools/evaluate_v80_en.py --model-dir reports/v80
python -m unittest discover -s tests/python -p 'test_v80_en.py' -v
python -m unittest discover -s tests/python -p 'test_v7[789]*.py' -v
```

Веса MiniLM изменены в части квантизации и распространяются с Apache License 2.0 в `encoder/LICENSE`, ссылкой на модель и описанием изменений в `encoder/manifest.json`. Неизменённый fastText LID внутри основы v79 — CC BY-SA 3.0: [атрибуция](fasttext-attribution.txt). Исходные письма не публикуются в Git, веса передаются отдельным архивом.
