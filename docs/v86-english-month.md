# Английская v86: новый месяц на100000 других письмах

Пользователь18 ноября разрешил добавить ранее предложенную HAM-поддержку и
повторно потребовал запустить месяц с отчётами. Окно **18 ноября–17 декабря2026
включительно**. Отдельная кампания `v86-en-month-20261118`, ветка
`mailguard-v86-english-month-20261117`, draftPR12. Старые v82/v84/RU/ES/TR не меняются.

## Фактический корпус и расположение

TRAIN **192890**: **100000 новых** (99902SPAM/98HAM) плюс **92890 прежних HAM**.
Старые HAM не считаются новыми. Состав закреплён research/v86/frozen.json.
Нормализованные тексты находятся только в `.cache/v86/corpus/train.jsonl.gz`;
исходный новый core — `.cache/v86/candidates/cohort-100000.jsonl.gz` в локальной
рабочей среде. В Git только код/manifest/агрегаты, ни сырых писем, ни весов.
Runner воспроизводит корпус из публичных SHA256-pinned источников и сохраняет
тексты только в Actions cache. Потеря cache не разрешает менять frozen manifest.

Новый core: Spam Archive2011 (фиксированный префикс200000 файлов) и полностью
прочитанные2018–2025 https://untroubled.org/spam/ ; TREC-06 зеркало revision
0c16fa9f7d6c24927a34f2dea3712152595374e8; два HAM из Nigerian_5.csv,
https://doi.org/10.5281/zenodo.8339691 . Все конкретные ссылки/хеши и label maps
сохранены в research/v86/*audit.json и archive-sources.json. Префикс2017 не включён.
Из114883 уникальных кандидатов6241 исключён относительно всей v84 TRAIN/SELECT
и v85 TRAIN/SELECT/TEST по identity/family/20-word windows. Из108642 оставшихся
выбран outcome-blind core100000; fingerprint
4a82d536c469e64448f522597fbbea2544707a735d61fb6911908a3b371847a6.
Семантическая независимость всех near duplicates не установлена.

Spam Archive разрешает unrestricted use, но его метки — слабые spam-trap SPAM.
У TREC-зеркала стандартная лицензия не найдена; сохраняется исходная атрибуция
TREC. Zenodo заявляет CC BY4.0; атрибуция Champa/Rabbi/Zibran2023 и исходных
компонентов сохраняется, secondary HAM provenance неполон. Поддержка наследует
метки старых источников; provenance Merged-public остаётся неполным.
См. также docs/v84-source-attribution.md. Только native email subject/body;
нет SMS/чатов/синтетики/переводов/клиентской почты и выдуманных HAM.

SELECT **22790** (10589SPAM/12201HAM) — прежний неизменный **development**,
исключён из градиентов. Новый независимый TEST не создан: test_rows=0,
пустой registry не выдаётся за измеренный тест. Старые CAL/TEST/100k/Nazario
были потреблены в v84 TRAIN; их оценки больше не независимы. Fitted98 выбирается
на том же SELECT. Основной фиксированный порог0.04897100105881691. Нет обещания
98%/10ppm или автоматического внедрения модели.

## Родитель, бюджет и точное восстановление

Первый parent — именно согласованный и проверенный v84 checkpoint **46000**
за17 ноября, run44026491168, artifact14307413784, SHA256
2e62947281989573c47e322e2dd372a9d0690750f4490c9238f9f962ef17e685.
Более новые v84 состояния не подставляются: exposure ledger поддержки закреплён
вместе с этим parent. Это отдельный эксперимент, не скрытое продолжение v84.
В baseline этого parent fixed TP10394/FP579/FN195/TN11622; fitted98
TP10378/FP548/FN211/TN11653. Все значения — development, не новый тест.

92890 старых HAM имеют остаток **113027 предъявлений**:72753 ещё по одному,
20137 ещё по два. Эти счётчики унаследованы; campaign/date не обнуляет их.
Новый core начинает с0, максимум3 на каноническую строку по ветке наследования.
Полный TRAIN99902SPAM/92988HAM; максимум3 прохода,30 завершённых дат,
**до500 optimizer steps /8000 разных строк за дату**, batch16,CPU-only.
Сеансы64 и остаток входят в один исходный дневной бюджет500, не в два бюджета.
Небольшой или остановленный корпус не крутится принудительно все30 дней.

LoRA/head,26 Adam states и RNG наследуются из parent. Новые корпус/order и
линейный scheduler планируются явно ровно один раз, начиная с текущего LR
parent. Позже восстанавливаются собственные v86 Adam/scheduler/RNG/order/
cursor/exposures/active_seen/hard_indices.24 внутренних LoRA matrices и head
обучаются; all-MiniLM-L6-v2 revision1110a243fdf4706b3f48f1d95db1a4f5529b4d41
полностью заморожен, hash проверяется до/после invocation.

Ошибки на TRAIN до градиента получают loss multiplier2; HAM — исходный cost2,
source/class weights ограничены. Наблюдавшиеся TRAIN-ошибки сохраняются в state
как индексы и приоритизируются в следующем проходе. Правильная поддержка остаётся;
это не заявление, будто все100000 писем уже являются ошибками модели.
Early stop после исправления25 ноября:3 неулучшающиеся завершённые SELECT-сессии
с начала кампании, либо3 эпохи/лимит предъявлений/конец окна. Исключение epoch0
убрано. Best заменяется только без регрессии fixed TP/FP, fitted98 FP и log-loss.

Незавершённая дата сохраняет исходные session/budget/target. Никакого холодного
старта при потере state, переноса checkpoint другого эксперимента, повторной
завершённой даты, будущих дат и градиентов после17 декабря. Публикация request
через expected_sha/CAS, force запрещён. PR остаётся draft/unmerged.

## Запуск и ежедневный отчёт

Workflow `.github/workflows/v86-english-month.yml` запускается synchronize PR12,
не имеет cron. Для него один собственный месячный управляющий `Automation_f14c4175ce848191bab9953fec356eab`; не дублировать.
Первый run44323525290: https://github.com/Kirusha-dk/MailGuard/actions/runs/44323525290 .
После первого18 ноября остаётся29 утренних запусков19 ноября—17 декабря
по Europe/Moscow, flexible08:00–09:00. Отчёт выдаётся и при отсутствии новых шагов.
Он проверяет running/queued именно v86/его ветку, скачивает последний неистёкший
`mailguard-v86-en-20261118-state` или `mailguard-v86-en-20261118-progress`,
сверяет фактические step/date/stop, затем продолжает незавершённую сессию либо
ставит сегодняшнюю дату с expected_min_step не ниже подтверждённого шага.

Каждый запуск даёт итог «Английская v86 — отчёт за YYYY-MM-DD», в том числе при
сбое/блокировке/stop/нуле шагов. Нужны run, реальный статус, новые unique core и
support rows/optimizer steps, phase отдельно от inherited46000/global, фактическое
восстановление,24LoRA/frozen backbone. Для незавершённого run только подтверждённый
milestone; cached session steps не являются новыми invocation steps. Для полной
сессии TP/FP/FN/TN, recall, FP/HAM/FPR на SELECT development, fixed и fitted98,
сравнение с последней завершённой датой/parent baseline. Отчёт также сохраняется
в reports/v86-daily; Git не заменяет ответ пользователю.

Перед первыми градиентами `v86-bootstrap-20261118` долговременно сохраняет
неизменный parent/provenance/pinned backbone manifest. Собственные state/weights
только в отдельных artifacts и experimental prereleases. Приstop, каждых7
завершённых датах и17 декабря сохраняются checkpoint, best adapters, metadata,
источники/условия и pinned backbone manifest без сырых писем. Ошибку публикации
исправлять без новых градиентов. Послеstop и проверенного пакета приостановить
только этот v86 управляющий; новый месяц автоматически не создавать.

25 ноября добавлена zero-gradient preflight остановка для уже накопленной
регрессии. Сессия24 ноября и исходный budget сохраняются; rollback floor49500.
Контрольная остановка архивируется отдельным immutable tag с суффиксом
-quality-stop, не перезаписывая опубликованный weekly пакет. Исследовательские
ремонты находятся отдельно в draft PR13; исходные parent/frozen/окно не менялись.
