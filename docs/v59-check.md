# Проверка MailGuard v59

v59 — исследовательская версия. На новом тесте из 11 831 письма профиль high-recall нашёл 66,13% спама и дал 1 FP среди 1 968 ham. У v57 на том же тесте: 26,48% и 1 776 FP. Цель 95% не достигнута.

На старой английской/CSDMC почте high-recall v59 показал 92,01% и 58 FP против 92,89% и 51 FP у v57. Поэтому v59 сохраняется как эксперимент, пригодный для отдельной проверки. Обычная почта нового теста — исторический китайский корпус; спам также включает июнь–сентябрь 2026 года. Качество на письмах заказчика не подтверждено.

[Полный результат](../reports/v59-result.json), [аудит данных](../reports/v59-data-audit.json), [завершённый запуск](https://github.com/Kirusha-dk/MailGuard/actions/runs/38371588029), [постоянный пакет модели для владельца репозитория](https://github.com/Kirusha-dk/MailGuard/releases/tag/untagged-03a59e9ae9595d773e59).

## 1. Подготовить письма

Экспортируйте каждое письмо целиком в формате `.eml`: исходные заголовки, MIME и тело. Не преобразовывайте письма в CSV, скриншоты или один текстовый файл.

Создайте две отдельные папки:

- `customer/ham` — обычные письма, которые нельзя отправлять в спам;
- `customer/spam` — подтверждённый спам.

Вложенные папки допустимы. Проверка считает все читаемые `.eml`, в том числе дубликаты, и отдельно сообщает дубликаты и противоречивые метки. Для содержательной проверки нужны реальные письма из обоих классов. Подписные рассылки размечайте по правилам вашей организации.

## 2. Скачать код и модель

Откройте ветку `mailguard-v48-calibrated` репозитория `Kirusha-dk/MailGuard`. Скачайте её через **Code → Download ZIP** и распакуйте.

Владелец репозитория скачивает `mailguard-v59-model.tar.gz` и `mailguard-v59-model.sha256` из draft release соответствующего запуска Actions. Для другого проверяющего передайте эти два файла отдельно: черновик релиза ему может быть недоступен.

Поместите архив модели и папку `customer` рядом с `Dockerfile.customer`.

## 3. Запустить

Нужны Docker и терминал. Следующие команды выполняются из папки с `Dockerfile.customer` на Linux/macOS или в WSL:

```sh
sha256sum -c mailguard-v59-model.sha256
tar -xzf mailguard-v59-model.tar.gz
docker build -f Dockerfile.customer -t mailguard-v59-check .
docker run --rm --network none \
  -v "$PWD/v59-full:/model:ro" \
  -v "$PWD/customer:/data:ro" \
  -v "$PWD/results:/results" \
  mailguard-v59-check \
  --model-dir /model \
  --ham /data/ham --spam /data/spam \
  --output /results/conservative --profile conservative
```

Перед запуском создайте `results` командой `mkdir -p results`. Сборке Docker нужен интернет для установки зависимостей. Во время проверки доступ к сети отключён; письма остаются на вашем компьютере.

Для второго профиля повторите `docker run`, заменив конец команды на `--output /results/high-recall --profile high-recall`. Профиль и порог фиксированы; скрипт не дообучает модель на ваших письмах.

## 4. Посмотреть результат

В папке выбранного профиля появятся:

- `summary.txt` — краткий итог;
- `summary.json` — числа для сравнения, версия и хеши модели;
- `predictions.csv` — решение по каждому файлу;
- `errors.csv` — FP, FN и нечитаемые письма.

Охват спама — `TP / (TP + FN)`. Частота ложных срабатываний — `FP / (FP + TN)`, то есть доля среди обычных писем. При повторной проверке выбирайте новую папку результатов: существующий отчёт скрипт не перезаписывает.

Для обсуждения проверки достаточно итогового `summary.json`, количества писем каждого класса и правил разметки. Письма, заголовки и списки адресов отправлять не требуется.
