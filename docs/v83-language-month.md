## Ежедневный испанский отчёт

Существующий RU/ES управляющий ежедневно публикует явный итоговый ответ
«Испанская модель — отчёт за YYYY-MM-DD», также при сбое, отсутствии новых
шагов или штатной остановке. Отдельный cron/второй управляющий не создаётся.
В отчёте нужны фактический run, статус, новые/суммарные optimizer steps,
восстановление состояния, изменения48 LoRA matrices и замороженный backbone,
TP/FP/FN/TN, recall и FP/HAM при0.5 на SELECT (development), сравнение со
вчерашними метриками, причина остановки/остаток до3 эпох. Ошибки на HAM
показываются даже при росте recall. TEST не открывается, автоматического
принятия в продукт нет. RU показывается отдельно и не скрывает отчёт ES.
Результат сохраняется и в reports/v83-daily, но Git-запись не заменяет
итоговый пользовательский ответ. Расписание сохранено: утро по Москве.

## TR: отдельная турецкая кампания

Окно TR:4 ноября–3 декабря2026 включительно; `v83-tr-20261104`, request
research/v83/tr.json. До100 optimizer steps за дату,3 эпохи максимум, те же
правила ранней остановки и строгого восстановления; отдельные адаптеры,
checkpoint и artifact `mailguard-v83-tr-20261104-state`. RU/ES сохраняют свои
окна2 ноября–1 декабря и свои веса. ES-сессия за4 ноября уже завершена: при
обновлении общего workflow повтор той же даты обязан выполнить0 новых шагов.

Используются два опубликованных корпуса реальной турецкой email-почты:
[UCI Turkish Spam V01](https://doi.org/10.24432/C5WG7F), CC BY4.0, и
[Turkish Mail Dataset Normal/Spam](https://www.kaggle.com/datasets/emrahaydemr/turkish-mail-dataset-normalspam),
версия1. Автор второго корпуса требует при использовании цитировать
Şimşek & Aydemir2022, https://doi.org/10.55195/jscai.1104694, но стандартная
лицензия не указана. Это условие сохраняется в source metadata; нельзя
представлять весь объединённый набор как CC BY4.0. Сырые письма не публикуются.

Архивы и CSV закреплены SHA256. В UCI CSV метка находится в последнем поле;
124 записи с лишними запятыми восстанавливаются объединением текстовых полей.
Неразмеченный footer исключён. Фактически329 SPAM+496 HAM, а не описанные
330+496; недостающая метка не выдумывается. Во втором архиве515 SPAM+502 HAM;
ARFF-копия исключена. Используется только текст, без имени файла/источника/метки
в признаках. Исходные метки сохраняются.

После fastText tr>=0.8, удаления дубликатов/конфликтов и family-disjoint split:
TRAIN1000(451 SPAM/549 HAM), SELECT203(89/114), TEST206(92/114).
Фиксация:research/v83/tr-frozen.json. Правила минимальных классов не снижались;
UCI без второго источника имел лишь22 SELECT SPAM и не прошёл gate.
TEST не открывается тренером. Порог0.5, SELECT development, при89 SELECT SPAM
подбор98%-го квантиля не выполняется. Не заявлять перенос на всю почту/10ppm.

Единственный существующий месячный управляющий расширяется на TR; отдельный
cron/task не создаётся. Каждый день нужен явный отдельный турецкий отчёт по
образцу ES с фактическими шагами, восстановлением состояния, TP/FP/FN/TN,
recall и FP/HAM. Для TR окно своё; после1 декабря RU/ES не обучаются, но TR
может завершаться до3 декабря. Новые кампании автоматически не продлеваются.
