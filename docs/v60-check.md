# Проверка MailGuard v60

v60 — исследовательская версия с обучением на новых апрельских письмах, отдельным учётом недавнего спама и Unicode CNN среди кандидатов. Итоговый вариант выбирается по SELECT, пороги — по SELECT и CAL. Майский TEST и прежний TEST v59 в обучение не входят.

Итоговый ансамбль сочетает новый разреженный классификатор, Unicode CNN и сохранённый score v59 через линейную модель. Нейросеть обучена четыре эпохи; выбрана четвёртая.

High-recall:

| Проверка | HAM | Recall v59 | FP v59 | Recall v60 | FP v60 |
|---|---:|---:|---:|---:|---:|
| Новые 4 146 писем | 313 | 71,61% | 5 | 78,53% | 5 |
| Повторные 11 831 письма v59 | 1 968 | 66,13% | 1 | 71,58% | 0 |
| Повторные 44 615 английских/CSDMC писем | 24 017 | 92,01% | 58 | 89,72% | 42 |

Цель 95% не достигнута. На новой обычной почте 5/313 FP, то есть 1,60% — выше желаемой частоты. На старой почте recall снизился. Профиль conservative особенно ухудшился: 7,10% на новом TEST, 9,08% на повторном TEST v59 и 14,36% на старой английской почте. Он сохранён для воспроизводимости, но для использования не рекомендуется. v60 не заменяет v59/v57 целиком.

В новом тесте 4 146 писем: 3 833 SPAM и 313 HAM. 313 HAM недостаточно для подтверждения очень редких FP. Прежние китайские и англоязычные тесты проверяются отдельно и обозначены как повторные. Качество на письмах заказчика пока не подтверждено.

## 1. Подготовить письма

Создайте две отдельные папки `customer/ham` и `customer/spam`. Экспортируйте каждое письмо целиком в `.eml`, сохранив заголовки, MIME и тело. Вложенные папки допустимы; в каждой категории нужно хотя бы одно письмо. Рассылки размечайте по правилам своей организации.

Для оценки используйте заранее размеченную выборку, которую не отбирали по ошибкам модели. Проверка учитывает все читаемые `.eml`, включая повторы; их количество и противоречивые метки сообщает отдельно.

## 2. Скачать код и модель

Скачайте ветку `mailguard-v48-calibrated` репозитория `Kirusha-dk/MailGuard` через **Code → Download ZIP** и распакуйте.

Владелец репозитория скачивает `mailguard-v60-model.tar.gz` и `mailguard-v60-model.sha256` из черновика релиза **MailGuard v60 — independent May evaluation**. Для другого проверяющего передайте эти два файла отдельно: черновик релиза ему может быть недоступен.

Поместите архив модели, файл контрольной суммы и папку `customer` рядом с `Dockerfile.customer`.

## 3. Запустить

Нужны Docker и терминал Linux/macOS или WSL. Все команды выполняйте из папки с `Dockerfile.customer`:

```sh
sha256sum -c mailguard-v60-model.sha256
tar -xzf mailguard-v60-model.tar.gz
mkdir -p results
docker build -f Dockerfile.customer -t mailguard-v60-check .
docker run --rm --network none \
  -v "$PWD/v60-full:/model:ro" \
  -v "$PWD/customer:/data:ro" \
  -v "$PWD/results:/results" \
  mailguard-v60-check \
  --model-dir /model \
  --ham /data/ham --spam /data/spam \
  --output /results/high-recall --profile high-recall
```

При нехватке памяти добавьте `--batch-size 16`. Для воспроизведения неудачного conservative-профиля замените конец команды на `--output /results/conservative --profile conservative`; этот профиль не рекомендуется для использования.

Сборке нужен интернет для установки библиотек. Проверка работает на CPU, без доступа к сети; письма остаются на вашем компьютере. Модель и пороги во время проверки не меняются.

## 4. Посмотреть результат

Откройте `results/high-recall/summary.txt`. Рядом сохраняются `summary.json`, решения по файлам в `predictions.csv` и ошибки в `errors.csv`.

- **Spam recall** — доля найденного спама: `TP / (TP + FN)`.
- **FP** — обычные письма, попавшие в спам; **FPR** — их доля среди всех обычных писем.
- **FN** — пропущенный спам.
- **failed** — нечитаемые файлы; при ненулевом значении проверка неполная.

Для повторного запуска укажите новую папку результатов. Для обсуждения достаточно `summary.json`, периода выборки и правил разметки; тексты писем и адреса передавать не требуется.
