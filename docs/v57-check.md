# Проверка v57 на своих письмах

Экспериментальная версия для проверки на отдельной размеченной выборке. Качество на почте заказчика пока не подтверждено. Проверка не обучает модель и не меняет её порог. Письма обрабатываются локально.

Нужны Linux или macOS, Git и запущенный Docker. Одно письмо — один файл `.eml`. Для CSV или mbox нужен отдельный загрузчик.

## 1. Скачать код

```bash
git clone --branch mailguard-v48-calibrated --single-branch https://github.com/Kirusha-dk/MailGuard.git MailGuard-v57
cd MailGuard-v57
mkdir -p model mail/spam mail/ham results
```

Все следующие команды выполняйте из папки `MailGuard-v57`.

## 2. Скачать модель

Откройте [запуск v57](https://github.com/Kirusha-dk/MailGuard/actions/workflows/v57-preserved.yml?query=branch%3Amailguard-v48-calibrated). После завершения скачайте в разделе **Artifacts** архив **mailguard-v57-evidence**. Распакуйте его в папку `model`.

Для полного запуска должны существовать четыре файла:

```bash
ls model/v57-full/model.joblib \
   model/v57-full/v54/model.joblib \
   model/v57-full/v54/neural.pt \
   model/v57-full/v55/model.joblib
```

Папка `v57-smoke` содержит модель небольшой технической проверки. Для своей итоговой проверки используйте `v57-full`. Папки `v54` и `v55` внутри неё нужны для работы v57. Если ZIP распаковался в дополнительную папку, перенесите `v57-full` непосредственно в `model`.

Артефакт хранится 90 дней. Контрольная копия модели также сохраняется в черновике выпуска GitHub, доступном владельцу репозитория.

## 3. Подготовить письма

Скопируйте заранее размеченные письма в две папки:

- спам — `mail/spam`;
- обычную почту — `mail/ham`.

В обеих папках должно быть хотя бы одно письмо. Вложенные папки поддерживаются. Начните с небольшой выборки, например 500 спам-писем и 500 обычных. Для оценки редких ложных срабатываний затем нужна существенно более крупная отдельная выборка обычной почты, включая рассылки и письма на разных языках.

Выбирайте письма до запуска модели. Не исключайте сложные письма по её результатам. Передавать письма разработчику не требуется.

## 4. Собрать окружение

```bash
docker build -f Dockerfile.customer -t mailguard-v57-check .
```

На этом шаге нужен интернет для скачивания Python и библиотек. Письма в образ не копируются.

## 5. Запустить проверку

```bash
docker run --rm --network none \
  -v "$PWD/model:/model:ro" \
  -v "$PWD/mail:/mail:ro" \
  -v "$PWD/results:/results" \
  mailguard-v57-check \
  --model-dir /model/v57-full \
  --spam /mail/spam \
  --ham /mail/ham \
  --profile conservative \
  --output /results/check-01
```

v57 сохраняет все положительные решения v54 и добавляет срабатывания выбранного режима v56. Ложные срабатывания v54 тоже сохраняются.

Этот запуск использует строгий режим `conservative`. Его порог уже сохранён в модели; на ваших письмах он не подбирается. Контейнер работает на CPU, сеть отключена, письма и модель доступны только для чтения.

Для отдельного сравнения второго режима на **тех же письмах** повторите команду, заменив `--profile conservative` на `--profile high-recall`, а `--output /results/check-01` на `--output /results/check-02`. Второй режим допускает больше FP при выборе порога. Названия режимов не гарантируют конкретные показатели на вашем потоке.

## 6. Посмотреть результат

```bash
cat results/check-01/summary.txt
```

- **Spam recall** — доля обнаруженного спама.
- **FP** — обычные письма, ошибочно признанные спамом.
- **FPR** — FP, делённые на количество обычных писем.
- **FN** — пропущенный спам.
- **failed** — файлы, которые не удалось прочитать. При ненулевом значении проверка неполная.
- **Duplicate content / conflicting labels** — повторы писем и повторы с противоречивой разметкой. Повторы учитываются в итоговых цифрах.

Рядом сохраняются `summary.json`, `predictions.csv` с решениями по каждому письму и `errors.csv` со списком ошибок. CSV содержат имена файлов и идентификаторы; оставьте их у себя. Для обратной связи достаточно `summary.txt`, периода сбора и состава выборки. Для сравнения с рабочим фильтром проверяйте его на тех же письмах.

## Если запуск не получился

- **Docker daemon / permission denied**: запустите Docker и проверьте права пользователя.
- **No .eml files**: проверьте пути и расширения; CSV, mbox и ZIP автоматически не читаются.
- **File not found / Component hash mismatch**: распакуйте полный артефакт ещё раз и проверьте четыре пути из шага 2. Не смешивайте файлы разных запусков.
- **Output already contains a report**: замените `check-01` на новое имя папки.
- При нехватке памяти добавьте к команде `--batch-size 16`.
