# MailGuard v77: CPU-модель и честная проверка RU/EN

**Обновление v78:** прежний внешний источник из этой страницы исключён из оценки из-за 9 673 конфликтующих меток для канонически совпадающих текстов. Число 13,04% ниже сохранено как исторический результат запуска, но его нельзя считать надёжной оценкой качества. [Аудит и английская v78](v78-en.md).

**Цель «не менее 80% спама на произвольных 10 000 русских и английских писем» пока не достигнута.** Сохранена работающая модель и воспроизводимые проверки. Версию нельзя считать готовой к автоматическому удалению почты.

## Что показал запуск 18 октября 2026 года

Здесь recall — доля найденного спама, FP — обычные письма, ошибочно названные спамом. Это разные показатели; accuracy не подменяет recall.

| Набор | Режим | Писем | Найдено спама | Recall | FP / обычных писем |
|---|---|---:|---:|---:|---:|
| Отложенная часть исторического почтового корпуса | low-fp | 10 000 | 3 911 / 4 554 | 85,88% | 6 / 5 446 |
| Тот же набор | balanced | 10 000 | 4 401 / 4 554 | 96,64% | 32 / 5 446 |
| Другой исторический источник после удаления пересечений | low-fp | 6 556 | 204 / 1 565 | 13,04% | 14 / 4 991 |
| Тот же внешний источник | balanced | 6 556 | 681 / 1 565 | 43,51% | 257 / 4 991 |

Первый тест содержит **9 997 английских и лишь 3 русских письма**. На русских: `low-fp` нашёл 1 из 3, `balanced` — 2 из 3. Обычных русских писем в почтовом тесте нет. Этих данных недостаточно, чтобы подтвердить качество русского языка или его FPR. Русская модель обучалась преимущественно на Telegram; это явно обозначенный вспомогательный источник, а не проверка электронной почты.

Внешний источник — `sniff07/phishing-dataset` (GitHub), ревизия `c21f524c014a49626dc61322a5f7b3194ac5c7d1`. Из 24 704 строк после нормализации, удаления повторов и проверки пересечений со всем исходным почтовым корпусом осталось только 6 556 писем. Набор не дополняли повторами до 10 000. Происхождение всех исходных сообщений у перепубликатора не подтверждено. Ранее этот источник изучался другими версиями проекта; v77 на нём не обучалась и пороги на нём не выбирала.

**Вывод:** v77 распознаёт знакомое распределение, но плохо переносится на другой источник. Значение 85,88% не доказывает выполнение общей цели. Следующий необходимый материал — размеченные реальные RU/EN письма со спамом и обычной почтой, с отдельными периодами для обучения и итоговой проверки.

Полные агрегаты: [контрольный тест](../reports/v77-result.json), [его фиксация](../reports/v77-frozen.json), [внешний тест](../reports/v77-external-result.json), [его фиксация](../reports/v77-external-frozen.json).

## Что изменено

- Два NBSVM-классификатора для каждого языка: слова и символьные сочетания; выбор комбинации и порога только на CAL.
- TRAIN: 70 000 английских и 13 950 русских текстов; символьный английский классификатор использует 30 000. CAL: 12 000 EN и 2 513 RU. Символьные признаки строятся блоками, чтобы обучение укладывалось в память.
- Для длинных текстов сохраняется начало и конец: до 10 000 символов для слов и 4 000 для символьных признаков.
- Чтение MIME, HTML, UTF-8, объявленных кодировок и восстановление CP1251/KOI8-R. Служебные антиспам-заголовки не используются как признаки.
- Повторы и противоречивые метки исключаются; все префиксные группы официальной TEST-части защищены от TRAIN/CAL. Семантические повторы этим полностью не исключаются.
- Веса и пороги записаны до оценки TEST. SHA256 модели проверяется после оценки. Внешняя проверка использует те же веса и пороги.
- Работает на CPU без PyTorch. Проверены 9 тестов и запуск на `.eml`.

## Проверить собственные письма

Скачайте код ветки `mailguard-v77-ru-en-baseline`. Установите Python 3.12 и зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-v77.txt
```

Распакуйте архив весов в `model/`, чтобы появился `model/model.joblib`. SHA256 файла:

```text
7fe0ff5147b7f252cb471e41cf7f46f26537314514cd22f5492c045d9a9a98af
```

Разложите заранее размеченные `.eml` в `mail/spam` и `mail/ham`. Подпапки разрешены. Обе папки должны содержать письма. Затем:

```bash
python tools/v77_mail.py \
  --model model/model.joblib \
  --spam mail/spam --ham mail/ham \
  --profile low-fp --output results/check-01
```

Результат — `summary.json` и `predictions.csv`. В них нет текстов писем. Повторы исключаются из метрик; противоречивые метки исключают обе копии. Непрочитанные, слишком короткие и неподдерживаемые тексты учитываются отдельно. Неподдерживаемый язык не превращается автоматически в обычную почту. `score` — оценка SVM, **не вероятность**.

`balanced` допускает больше FP и не является заменой `low-fp` с теми же гарантиями. У текущей версии на внешнем тесте этот режим дал 5,15% FP; выбирать его для рабочей почты по результату первого теста нельзя.

`Dockerfile.v77-check` предоставлен как дополнительный способ запуска; Docker-сборка в этой сессии не проверялась. Проверены Python-команды.

## Повторить эксперимент

```bash
python -m unittest discover -s tests/python -p 'test_v77_ru_en.py' -v
python -u tools/train_v77_ru_en.py --output reports/v77
python -u tools/evaluate_v77_external.py --model reports/v77/model.joblib
```

Нужен интернет для первоначального получения источников. Ревизии и хеши зафиксированы кодом. Исходные тексты остаются в локальном `.cache/`; в Git и артефакты проверки попадают только веса и агрегаты. Старые версии сохранены. Ручной workflow `.github/workflows/v77-ru-en-cpu.yml` повторяет обучение и проверку без изменения рабочей модели.
