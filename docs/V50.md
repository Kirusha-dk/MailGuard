# v50 supervised neural complement

v49 selected the v48 estimator at a much stricter threshold, reducing recall
to 68.52%. It is not a replacement for the original 92.71% / 74 FP v48.

v50 trains a small supervised byte CNN from scratch on the full frozen TRAIN.
It reads 1024 UTF-8 bytes from the start and end of canonical visible mail.
Shared convolution filters of widths 3, 5 and 9 plus max pooling learn short
text patterns; this is not a language model with broad semantic understanding.
It complements v48 sparse features and does not use external inference APIs.

Eight fixed epochs run on CPU. Epoch selection uses the model-selection half
of validation. Blend weights 0, .1, .25, .5, .75 and 1 are compared on that
same development partition. Weight zero retains the v48 estimator, so a neural
branch is accepted only if it wins validation selection. The threshold is then
calibrated on the separate calibration half. No refit follows calibration.

The development allowance returns to v48's 0.12% FP per total validation mail
to isolate the representation change. This allowance does not guarantee <=100
FP on 100k mail; final actual FP is measured and reported. The objective remains
98% recall and <=100 FP. Neither target is guaranteed by the model design.

The smoke run uses 1000 rows and two epochs before full training. Reports include
training/validation losses, chosen epoch, all blend candidates, calibration,
per-source results, model checkpoints and hash-only engineering predictions.

The 81,688 public rows have already been inspected. They are an engineering
comparison, not an independent final test. They never enter TRAIN or calibration.
The available pool cannot establish a 100k pass. Production testing and eventual
integration with the customer's Rspamd pipeline remain separate work.

Local syntax checks passed. Torch is not installed in the local runtime, so
gradient/state-restoration tests run in the GitHub workflow after CPU Torch is
installed. The workflow stops before training if those tests fail.
