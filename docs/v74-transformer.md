# v74 — реальное дообучение многоязычной нейросети MailGuard

## Что изменилось

В версиях v68–v73 использовались в основном статистические модели поверх слов и сочетаний символов. v74 — отдельный эксперимент с предобученным **Transformer**.

Используется `microsoft/Multilingual-MiniLM-L12-H384` (MIT), **BERT/MiniLM, а не полная XLM-RoBERTa**. Токенизатор — `FacebookAI/xlm-roberta-base`. Эта пара поддерживается моделью MiniLM и позволяет применять один и тот же encoder для русского и английского. Модель компактнее полной XLM-R и предназначена для запуска на обычном GitHub CPU.

При обучении заморожены embeddings и первые девять блоков Transformer; **три последних блока, pooler и classifier получают градиенты и действительно обучаются**. Это не только обучение линейной головы. Максимальная длина — 96 токенов, одна эпоха, batch=8. Код: [tools/v74_transformer_finetune.py](../tools/v74_transformer_finetune.py).

## Какие данные допустимы

- Русский: ранее использованный CC0-набор Telegram; **чат — не электронная почта**.
- Английский: ранее использованные письма из публичного набора; права на все собранные оригинальные письма не подтверждены.
- TRAIN: до 650 сообщений каждого класса для RU и 1100 каждого класса для EN, всего 3500 сообщений.
- CAL: детерминированная выборка 1600 RU и 3200 EN, пороги выбираются **по HAM на CAL**.
- TEST: фиксированные прежние 5000 RU и 5000 EN из v68/v69. **Это повторная оценка, не новый источник.** По TEST не выбираются веса, пороги и архитектура.

## Что означают результаты

В отчёте представлены TP, FN, FP, TN, Recall, FPR отдельно по языкам и двум заранее заданным режимам. Режим `zero-cal-fp` должен получить ноль ложных срабатываний на **малой CAL**, но не гарантирует ноль на других данных. Режим `research-0p1pct-cal-fpr` допускает до 0,1% FP на CAL — на порядок больше целевого 0,01% FPR.

Модель и используемые веса записываются в отдельный GitHub Actions artifact, исходные сообщения не публикуются. Замороженные v64/v65/v69 не меняются.

## Как запустить

Откройте [workflow v74](../.github/workflows/v74-transformer-finetune.yml) и запустите через Actions -> Run workflow, либо внесите изменение в `tools/v74_transformer_finetune.py`.

Рабочее окружение: Python 3.12, PyTorch 2.5.1 CPU, Transformers 4.46.3. В начале тестируется математика CAL, групповые выборки и реальное размораживание Transformer. В конце workflow сохраняет в `reports/v74-transformer-*` агрегаты, а в artifact — checkpoint с весами и токенизатором.

## Условия принятия версии

Обнаружение не менее 90% спама **на любом независимом потоке 10 000 писем** из этих экспериментов подтвердить нельзя. Для переносимости нужны поставщики и периоды, не использовавшиеся для выбора архитектуры, а также отдельно настоящие размеченные русскоязычные `.eml`. Для заявления о FPR 0,01% нужен существенно больший независимый HAM-набор; даже 0 FP на нескольких тысячах недостаточно.

Итоговая защита ложных срабатываний Rspamd + MailGuard и приватность реальной почты заказчика должны проверяться отдельно от общественных корпусов.
