# MailGuard v81: отклонённый эксперимент по снижению FP

**Условие «меньше FP без потери обнаруженного спама» не выполнено. Кандидат не заменяет v80.**

На прежних 100 000 английских писем FP сократились с **586 до 584**, но потеряно **одно** ранее обнаруженное спам-письмо. На отдельном регрессионном наборе Nazario-2024 потеряно ещё одно: **230 → 229 из 247**. Обе выборки не пересекаются по идентичностям и группам первых 45 слов.

| Режим | Поймано спама / 46697 | Recall | FP / 53303 HAM | FN |
|---|---:|---:|---:|---:|
| v80 `recall-98` | 45738 | 97.94633% | 586 | 959 |
| Отклонённый `fp-rescue` | 45737 | 97.94419% | 584 | 960 |

В CLI и API по умолчанию используется неизменённый `v80-recall-98`. `fp-rescue` оставлен только для воспроизведения отклонённого эксперимента. Цель 98% с примерно 10 FP на миллион не достигнута; миллион писем не проверялся.

## Что проверялось

Исходная точка — точная v80 с SHA `6aa2e92b2e1ccfd764223eeea5d1c792e5ae15548ad60767be93023d690aa5c9` и её неизменённым порогом `recall-98`. Новый этап может только отменить положительное решение этой модели. Поэтому новые FP структурно не добавляются; отсутствие потери спама требует отдельной проверки.

На 11 502 SELECT-fit письмах обучены дополнительные линейный и нелинейный классификаторы смысловых признаков, а также дерево по пяти лексическим оценкам, двум смысловым оценкам, маске и семи текстовым признакам. Для альтернативы ближайших соседей использованы 16 042 TRAIN-письма из источников с известным происхождением. Сам Transformer не дообучался. В итоговом кандидате выбрано дерево; остальные новые модели в его веса не включены.

Рассмотрены 39 сочетаний оценок и заранее заданных разбиений: весь поток, преобладающий лексический детектор, три диапазона исходной оценки. Для каждой области порог отмены лежит ниже минимальной оценки **каждого** ранее пойманного спам-письма на SELECT-choose и CAL, с дополнительным запасом 0,25 IQR оценок обучающего спама. В области требуется минимум 100 защищаемых спам-писем на каждом разделе.

Первоначально лучший на SELECT вариант снимал 9 FP из 64. После CAL этот результат сократился до 0 на SELECT и 4 на CAL. До просмотра регрессии проверены и остальные варианты. Итоговый выбор использует суммарное снижение FP на SELECT/CAL при нулевой потере спама в обоих разделах. **CAL участвует в выборе модели и не является независимой оценкой её качества.** Ни один вариант не показал снятых FP сразу на обоих разработочных разделах.

Из четырёх снятых CAL FP одно — Enron, три — `Merged-public` с неполным происхождением. Поэтому разработочный выигрыш особенно нельзя переносить на настоящую почту. Разметка не менялась по предсказаниям модели.

Модель и пороги зафиксированы до регрессионной проверки. После её результатов параметры не менялись. Условие принятия: хотя бы один снятый FP на 100k, ноль потерянных индивидуальных обнаружений спама во всех десяти блоках и в Nazario-2024, ноль новых FP. Кандидат это условие нарушил и отклонён.

## Запуск

Python 3.12, Linux, CPU. Распакуйте экспериментальный ZIP полностью в `model`; внутри нужны `model.joblib`, `baseline/model.joblib`, `baseline/base/model.joblib` и `baseline/encoder/`.

```bash
git clone --branch mailguard-v81-en-fp --single-branch https://github.com/Kirusha-dk/MailGuard.git
cd MailGuard
python -m pip install -r requirements-v80.txt
python tools/v81_mail.py --model model/model.joblib \
  --spam mail/spam --ham mail/ham --profile v80-recall-98 --output results/baseline
```

Одна `.eml` на письмо, отдельные заранее размеченные SPAM/HAM папки. Проверка локальная после установки зависимостей. Язык с недостаточной уверенностью исключается с явным счётчиком, повторы и противоречивые идентичности исключаются. В CSV нет текстов писем. Для воспроизведения **отклонённого** режима замените профиль на `fp-rescue` и выберите новую выходную папку. Итоговая оценка учитывает оба этапа; неотрицательная оценка означает SPAM.

## Повторить эксперимент

Подготовьте точные наборы по [v79](v79-en-100k.md) и [v80](v80-en-phishing.md). Encoder уже включён в ZIP. Для новых выходных папок:

```bash
python -m pip install -r requirements-v80-training.txt
python tools/audit_v81_cohorts.py
OMP_NUM_THREADS=3 OPENBLAS_NUM_THREADS=3 MKL_NUM_THREADS=3 TOKENIZERS_PARALLELISM=false \
  python -u tools/train_v81_fp.py --baseline model/baseline/model.joblib --out reports/v81-reproduced
python tools/evaluate_v81_fp.py --model-dir reports/v81-reproduced
python tools/check_v81_cli.py --model-dir reports/v81-reproduced --output .cache/v81/cli-reproduced
python -m unittest discover -s tests/python -p 'test_v7[789]*.py' -v
python -m unittest discover -s tests/python -p 'test_v8*.py' -v
```

Старый способ выбора только по SELECT доступен через `--selection-mode select-only`. Все варианты используют только development; итоговые письма для настройки не читаются. Кэши проверяют состав, тексты, модель, код и маску вычислений. Регрессионные блоки можно возобновлять только с теми же контрольными суммами.

Пройдены 35 тестов. Реальный CLI/API совпал на 60 английских письмах, включая 4 специально включённых CAL FP; это проверка интерфейса, не тест обобщения. Исключены три других языка, обработаны повтор и конфликт разметки. Одиночные и групповые решения совпали, максимальная разница оценок — 0. Параллельные и исходные лексические оценки совпали точно на 128 TRAIN-примерах.

SHA256 отклонённого `model.joblib`: `b00e7223fbf2b51477a0a956f88a2c27260781cd619a8caa9ca860536f61edef`. Неизменённые v79/v80 и прежние отчёты сохранены. Атрибуции fastText и лицензия изменённого MiniLM находятся в `baseline/`; подробности лицензий — в инструкции v80.
