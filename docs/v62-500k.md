# Проверка v62 на 500 000 письмах

Модель v62 и оба её порога остаются зафиксированными. Проверка запускается на GitHub Actions: **MailGuard v62 on 500000 distinct emails**. Скрипт — `tools/evaluate_v62_500k.py`.

Используется сохранённый корпус `mailguard-v54-unique500k-corpus` из запуска 38092976048. Это 500 000 исторических публичных писем с проверкой уникальности идентификаторов, тел и нормализованных шаблонов. Корпус преимущественно состоит из спама; обычных писем гораздо меньше. Он уже изучался при разработке прежних версий.

Отчёт содержит три результата:

- `all`: весь корпус, включая письма, участвовавшие в разработке. Это проверка масштаба, а не независимая оценка качества.
- `no-development-overlap`: исключены идентификаторы и семейства из TRAIN, SELECT и CAL v62. Это повторная инженерная проверка.
- `development-overlap`: письма, пересекающиеся с указанными этапами.

FP делится на число обычных писем, а не на 500 000. Также приводится верхняя граница 95% интервала для FPR. Даже отсутствие FP на небольшом числе обычных писем не подтверждает качество уровня заказчика.

Сначала выполняется аудит корпуса. Затем пять заданий проверяют по 100 000 писем. Итоговый отчёт и предсказания сохраняются в артефакт `mailguard-v62-500k-result`; отчёт также сохраняется в репозиторий. Модель при этом не переобучается, пороги по этим письмам не подбираются.
