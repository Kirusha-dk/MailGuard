# v82: ежедневное продолжение обучения английской нейросети

Экспериментальная кампания: **20 октября — 18 ноября 2026 включительно**. Основная модель остаётся v80. Запуск обучения, изменение нейронных адаптеров и улучшение качества — разные результаты. Цель 98% Spam Recall при примерно 10 FP на миллион обычных писем пока не подтверждена. Гарантия для любых писем или каждого произвольного блока невозможна по имеющимся данным.

## Что обучается

Английская `sentence-transformers/all-MiniLM-L6-v2`, revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`; исходные float-веса safetensors, SHA256 `53aa51172d142c89d9012cce15ae4d6cc0ca6895895114379cacb4fab128d9db`. Лицензия исходной модели Apache-2.0: <https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2/blob/1110a243fdf4706b3f48f1d95db1a4f5529b4d41/LICENSE>.

В query/value attention всех шести слоёв добавлены обучаемые LoRA-матрицы rank 8, alpha 16; также обучается выходной слой. Всего **74 113 параметров**. Эти адаптеры меняют внутреннее представление текста; исходные матрицы backbone заморожены. Это отличается от v80/v81, где классификатор получает неизменяемые эмбеддинги. Ранее v74/v75 уже выполняли короткое дообучение части Transformer; v82 добавляет ограниченное продолжение между днями.

AdamW: LR 0.0002, warmup до 100 шагов, weight decay 0.01, gradient clipping 1.0, batch 16, максимум 192 токена из начала/конца письма. Вес обычной почты повышен вдвое, группы источник/класс взвешены по представленности. Эти настройки экспериментальные; штраф HAM сам по себе не гарантирует снижение FP без потерь спама.

## Данные и измерения

Используются опубликованные фиксированные TRAIN/SELECT из v79 и добавочного phishing-корпуса v80: **90 680 TRAIN и 22 790 SELECT**, только английский по прежнему фильтру. Архивы и pretrained-веса проверяются по хешам; итоговые manifests должны совпасть с `reports/v79-frozen.json` и `reports/v80-extra-frozen.json`. Семейства TRAIN/SELECT не пересекаются. Полное семантическое устранение близких дубликатов и независимость издателей не доказаны; ограничения v79/v80 сохраняются. Это исторические публичные данные, не клиентская почта.

Тренер читает только TRAIN/SELECT. CAL, прежние 100 000 писем и Nazario-2024 не участвуют в градиентах или ежедневном выборе. При подготовке корпуса прежний алгоритм читает идентичности и семейства всех разделов для исключения пересечений; это не подбор по результатам модели.

После сессии на SELECT выбирается порог примерно 98% recall и измеряется FP. **Этот recall получается подбором порога на той же выборке и не доказывает качество на новой почте.** FP при этом пороге и log loss используются только для выбора экспериментального checkpoint. Миллионного независимого HAM-теста нет. Ноль FP примерно на 300 000 независимых HAM дал бы лишь приблизительную одностороннюю 95%-ную верхнюю границу 10 FP/миллион при предположении одинакового распределения.

## Продолжение по дням

Одна сессия: до **500 optimizer steps** (до 8 000 предъявлений писем); 30 сессий — примерно 2.65 эпохи этого TRAIN. Дневное ограничение не означает новые размеченные письма каждый день: новых источников с проверенными метками автоматически не поступает. Максимум три эпохи; после первой эпохи три последовательные сессии без улучшения development-метрики останавливают оптимизацию раньше. Месяц — ограничение программы, не гарантия роста качества.

Checkpoint содержит LoRA/head, **Adam moments, scheduler, RNG, epoch, data cursor, завершённые даты и незавершённый бюджет**. Проверка метаданных запрещает незаметную смену корпуса/настроек/кампании. `expected_min_step` запрещает откат и холодный старт вместо продолжения. Повтор той же незавершённой сессии продолжает первоначальный бюджет; завершённая дата повторно не обучается. После прерывания сохраняются шаги до последнего checkpoint каждые 25 шагов; несохранённый хвост может быть воспроизведён. Итоговый отчёт включён в checkpoint и восстанавливается при обрыве публикации без дополнительных optimizer steps.

Workflow `.github/workflows/v82-neural-daily.yml` запускается push изменения `research/v82/cycle.json` на ветку `mailguard-v82-neural-month`. Имеющаяся месячная задача ChatGPT проверяет предыдущий run, обновляет запрос следующей даты и проверяет, что GitHub Actions действительно начал работу. Это двухчастная схема: задача запускает и проверяет; сам градиентный расчёт выполняет Actions. Если задача не сработает, ежедневного обучения не будет. Не нужно сливать workflow в основную ветку ради первого push-запуска.

Продолжение хранится в Actions artifact `mailguard-v82-english-20261020-state`, retention 45 дней. Небольшой development-отчёт коммитится в `reports/v82-daily/YYYY-MM-DD.json`; письма и веса в Git не попадают. Запись отчёта не запускает цикл заново. При ошибке следующий запуск сначала восстанавливает незавершённую сессию. При истечении/отсутствии checkpoint после первого дня продолжать с нуля запрещено.

## Локальное воспроизведение

```bash
python -m venv .venv
.venv/bin/python -m pip install torch==2.14.1+cpu --index-url https://download.pytorch.org/whl/cpu
.venv/bin/python -m pip install -r requirements-v82.txt
.venv/bin/python -m unittest discover -s tests/python -p test_v82_neural.py -v
.venv/bin/python tools/fetch_v82_inputs.py
.venv/bin/python tools/train_v82_daily.py --request research/v82/cycle.json
```

Скачивание и первичная обработка публичного корпуса требуют времени и нескольких GB диска; последующие Actions используют cache. CPU-запуск ограничен 100 минутами, шаг обучения — 55 минутами. Платный GPU не настроен. Checkpoint обучающего процесса не является готовой заменой модели в клиентском CLI.

`tools/check_v82_pretrained.py` проверяет на четырёх **выдуманных** примерах, что внутренние адаптеры меняются, исходные матрицы сохраняются, а 3+3 шага после восстановления совпадают с шестью непрерывными шагами. Это инженерная проверка, не измерение Spam Recall/FP.

## Условие принятия

Кандидат не заменяет v80 автоматически. Порог/сочетание моделей фиксируются по development/CAL до регрессионной проверки. Требуется сравнение **по идентичностям писем**: ни одно письмо со спамом, ранее обнаруженное выбранным режимом v80, не должно быть потеряно ни на старых 100 000, ни на 247 Nazario-2024; одновременно FP должны снизиться. Равенство суммарных TP не заменяет эту проверку. Эти уже просмотренные корпуса — регрессия, не независимое доказательство переноса. Для итогового заявления нужны отдельные не использованные при настройке английские источники и достаточный объём HAM. Если условие не выполнено, кандидат остаётся экспериментом, как отклонённая v81.
