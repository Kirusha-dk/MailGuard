Весь GenSpam исключён из обучения; это проверка одного исторического источника, не гарантия на произвольную почту. [Запуск v78 и полные результаты](docs/v78-en.md).

## Проверка на своих письмах

Нужны Git и работающий Docker; рекомендуется 4 ГБ свободной памяти. Команды ниже выполняются в Bash: Linux, macOS или Ubuntu в WSL2 на Windows с включённой [интеграцией Docker Desktop](https://docs.docker.com/desktop/features/wsl/). Одно письмо — один файл `.eml`. Проверка работает на CPU в контейнере `linux/amd64`; он проверен в GitHub Actions на Linux. На Apple Silicon Docker Desktop использует эмуляцию, поэтому запуск может быть медленнее; отдельные проверки macOS и Windows пока не выполнены.

### 1. Скачать код

```bash
git clone --branch mailguard-v48-calibrated --single-branch https://github.com/Kirusha-dk/MailGuard.git MailGuard-check
cd MailGuard-check
mkdir -p model mail/spam mail/ham results
```

Остальные команды выполняйте из `MailGuard-check`.

### 2. Скачать модель

Войдите в GitHub, откройте [запуск v64](https://github.com/Kirusha-dk/MailGuard/actions/runs/38615175304) и в **Artifacts** скачайте **mailguard-v64-frozen-model**. Распакуйте ZIP в `MailGuard-check/model`. Проверьте:

```bash
ls model/model.joblib model/v62/model.joblib
```

Артефакт хранится до 12 января 2027 года. [Постоянный пакет для владельца](https://github.com/Kirusha-dk/MailGuard/releases/tag/untagged-8b6b0866d3efb6058fbd) — отдельный черновик Release. Если используете его `.tar.gz`, распакуйте его в `model`; путь модели ниже остаётся `/model`.

### 3. Подготовить письма

Скопируйте заранее размеченный спам в `mail/spam`, обычную почту в `mail/ham`. Подпапки допустимы, обе папки должны содержать `.eml`. Начните с небольшой выборки, затем проверьте отдельный набор за новый период.

```bash
docker build --platform linux/amd64 -f Dockerfile.v64-check -t mailguard-v64-check .
```

Для сборки нужен интернет. Письма в образ не копируются.

### 4. Запустить проверку

```bash
docker run --rm --platform linux/amd64 --network none \
  -v "$PWD/model:/model:ro" \
  -v "$PWD/mail:/mail:ro" \
  -v "$PWD/results:/results" \
  mailguard-v64-check \
  --model-dir /model \
  --spam /mail/spam --ham /mail/ham \
  --profile conservative \
  --output /results/check-01
```

Модель и порог не меняются. `high-recall` распознаёт больше спама; `conservative` даёт меньше FP ценой пропусков. Для сравнения замените профиль и папку вывода на `/results/check-02`. При нехватке памяти добавьте `--batch-size 16`.

### 5. Прочитать результат

```bash
cat results/check-01/summary.txt
```

- **Spam recall** — доля обнаруженного спама; **FN** — пропущенный спам.
- **FP** — обычные письма, ошибочно признанные спамом; **FPR** = FP/HAM.
- **failed** — непрочитанные файлы; ненулевое значение означает неполную проверку.
- **Duplicate content / conflicting labels** — повторы и противоречивая разметка. Повторы учтены в итоговых числах.

Рядом сохраняются `summary.json`, `predictions.csv` и `errors.csv`. В CSV нет текстов писем; имена файлов и идентификаторы оставьте у себя. Для обсуждения достаточно `summary.txt` и периода выборки. Действующий фильтр сравнивайте на тех же письмах.

Если Docker не запускается, проверьте, что он включён. Если письма не найдены, проверьте пути и `.eml`. Если папка вывода уже содержит отчёт, используйте новое имя.

Код: `tools/` — обучение и применение моделей; `src/` — исходный C# проект с Rspamd. Качество на почте заказчика не подтверждено. Прежние версии сохранены: [v51](docs/v51-check-legacy.md), [v57](docs/v57-check.md), [v59](docs/v59-check.md), [v60](docs/v60-check.md), [v62](docs/v62-check.md).
