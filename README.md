# MailGuard

Фильтр спама с локальной обработкой писем.

## Проверка v51 на своих письмах

Этот запуск проверяет готовую модель на размеченных письмах. Он не обучает модель, не меняет порог и не подключается к рабочему почтовому фильтру. Rspamd и .NET для этой проверки не нужны.

Инструкция рассчитана на Linux или macOS, установленный Git и работающий Docker. Письма нужны в формате `.eml`: одно письмо — один файл. Для CSV или другого формата сначала нужен отдельный загрузчик.

### 1. Скачать код

Откройте терминал и выполните:

```bash
git clone --branch mailguard-v48-calibrated --single-branch https://github.com/Kirusha-dk/MailGuard.git MailGuard-check
cd MailGuard-check
mkdir -p model mail/spam mail/ham results
```

Все следующие команды выполняйте из папки `MailGuard-check`.

### 2. Скачать готовую модель

1. Войдите в GitHub и откройте [завершённый запуск v51](https://github.com/Kirusha-dk/MailGuard/actions/runs/38056209730).
2. Внизу страницы, в разделе **Artifacts**, скачайте **mailguard-v51-evidence**.
3. Распакуйте ZIP в папку `MailGuard-check/model`.

После распаковки должны существовать:

- `model/v51-full/model.joblib`
- `model/v51-full/neural.pt`

Проверьте их из терминала:

```bash
ls model/v51-full/model.joblib model/v51-full/neural.pt
```

Если файлы лежат глубже, перенесите папку `v51-full` непосредственно в `model`. Артефакт имеет ограниченный срок хранения; если ссылка уже недоступна, потребуется новый пакет модели.

### 3. Подготовить письма

Скопируйте заранее размеченные письма:

- спам — в `mail/spam`;
- обычную почту — в `mail/ham`.

Можно использовать вложенные папки. Скрипт читает только файлы с расширением `.eml`, включая `.EML`. В обеих папках должно быть хотя бы одно письмо. Разметку берите из своей проверенной выборки.

Проверьте небольшую выборку сначала: например, 500 спам-писем и 500 обычных. Для итоговой проверки используйте отдельный набор, который не отбирался по результатам модели.

### 4. Собрать окружение

```bash
docker build -f Dockerfile.customer -t mailguard-v51-check .
```

На этом шаге нужен интернет для скачивания Python и библиотек. Письма при сборке в образ не копируются.

### 5. Запустить проверку

```bash
docker run --rm --network none \
  -v "$PWD/model:/model:ro" \
  -v "$PWD/mail:/mail:ro" \
  -v "$PWD/results:/results" \
  mailguard-v51-check \
  --model-dir /model/v51-full \
  --spam /mail/spam \
  --ham /mail/ham \
  --output /results/check-01
```

Проверка работает на CPU. В терминале появится счётчик обработанных писем. У контейнера отключена сеть; модель и письма доступны только для чтения.

### 6. Посмотреть результат

Откройте `results/check-01/summary.txt` или выполните:

```bash
cat results/check-01/summary.txt
```

В отчёте:

- **Spam recall** — доля обнаруженного спама.
- **FP** — обычные письма, ошибочно признанные спамом.
- **FPR** — FP, делённые на количество обычных писем.
- **FN** — пропущенный спам.
- **failed** — файлы, которые не удалось прочитать; при ненулевом значении проверка неполная.
- **Duplicate content / conflicting labels** — повторяющиеся письма и повторы с противоречивой разметкой. Повторы учитываются в итоговых цифрах.

Рядом сохраняются `summary.json`, `predictions.csv` с решениями по каждому письму и `errors.csv` со списком FP, FN и непрочитанных файлов. В CSV нет текстов писем, но есть имена файлов и идентификаторы: эти отчёты оставьте у себя.

Для обратной связи достаточно прислать содержимое `summary.txt` и период, за который собрана выборка. Сами письма передавать не нужно. Это результат отдельной модели MailGuard; для сравнения с действующим фильтром проверяйте его на тех же письмах.

### Если запуск не получился

- **Docker daemon / permission denied**: убедитесь, что Docker запущен и текущему пользователю разрешена работа с ним.
- **No .eml files**: проверьте пути и расширения; CSV, mbox и архивы автоматически не читаются.
- **File not found** для модели: проверьте два пути из шага 2.
- **Output already contains a report**: для повторного запуска замените `check-01` на `check-02`.
- При нехватке памяти добавьте в конец команды `--batch-size 16`.
